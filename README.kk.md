## Жылдам бастау — бір нұсқаны таңдаңыз

> [!IMPORTANT]
> ### 🔑 API кілті қажет пе?
>
> | | Кілт қажет пе? |
> |---|---|
> | **A — барлығын нөлден, ЖИ-агенттермен іске қосу** | ✅ **Иә, OpenAI API кілті қажет.** Іске қоспас бұрын `.env` файлына жазыңыз. |
> | **B — хакатон барысында алынған нәтижелерді ғана қарау** | ❌ **Жоқ.** Кілт те, аккаунт та, интернет те қажет емес. |
> | **C — барлығын ЖИ-сіз қайта есептеу** | ❌ **Жоқ.** Дәл сол үш CSV, дәл сол рөлдер мен рет шығады. |
>
> Кілт болмаса және құралдың нәтижесін ғана көргіңіз келсе, бірден
> **B нұсқасына** өтіңіз — ол бірден жұмыс істейді.

### A · Барлығын нөлден, ЖИ-агенттермен бірге іске қосу

`.env` файлына кілт жазып, дәл осы екі команданы орындаңыз:

```bash
cp .env.example .env && echo "OPENAI_KEY=sk-АУЫСТЫРЫҢЫЗ" >> .env
./agent_run.sh
```

Шамамен 90 секунд және ағымдағы модельде шамамен $0.21.

### B · Хакатон барысында алынған нәтижелерді ғана қарау

Кілт қажет емес, модельге жүгіну жоқ:

```bash
./agent_run.sh --use-existing
```

### C · Барлығын ЖИ-сіз қайта есептеу

Дәл сол үш CSV, дәл сол рөлдер мен рет — тек тұжырымдамалар өзгереді:

```bash
./agent_run.sh --offline
```

### Қай интерфейс?

**Әдепкі бойынша — меншікті фронтенд.** Бұл жергілікті таратылатын статикалық
бет, браузерде өзі ашылады және интернетті қажет етпейді.

```bash
./agent_run.sh                   # меншікті фронтенд (әдепкі)
./agent_run.sh --ui gradio       # Gradio, жалпыға ортақ сілтеме бере алады
./agent_run.sh --ui none         # интерфейссіз, тек файлдар
./agent_run.sh --no-browser      # браузерді ашпау
```

Екі интерфейс те бірдей файлдарды оқиды, сондықтан әрқашан бірдей сандарды
көрсетеді. Екеуі де **орыс тілінде** ашылады; ағылшын және қазақ тілдері бір
басумен қолжетімді.

## 1. Шешімнің сипаттамасы және мақсаты

### Мәселе

Құқық қорғау органдары екінші деңгейлі банктің AML талдаушысына есірткі
саудасынан ақша алған клиенттердің тізімін береді — бұл **тізбектің төменгі
деңгейі**. Олардың үстінде кім тұрғаны, бұл ақшаны кім жинайтыны, кім арқылы
жылжытылатыны және оны түптеп келгенде кім басқаратыны қолмен қалпына
келтіріледі — бір түйінге бірнеше сағаттан.

### Шешім не істейді

**Кіріс:** 81 белгілі клиенттің **шығыс** аударымдарының 4 буын тереңдіктегі
жиыны (2026 шілде, банк ішіндегі аударымдар, 5 000 ₸ бастап) — 2 248 түйін,
3 119 қабырға, 4 840 транзакция.

**Шығыс:** бір сұраққа жауап — **2 248 клиенттің қайсысын алдымен тексеру керек
және неге**. Нақтырақ:

* әр түйінге сөздіктен **рөл**, **рөлге сенімділік** (0–1), **кластер** және
  **тексеру басымдығы** (0–1) беріледі;
* әр рөлге **сандары бар негіздеме** қоса беріледі — дәл ереже салыстырған
  сандар;
* бекітілген схемасы бар үш CSV файл;
* **веб-интерфейс**, онда шот нөмірі бойынша бірнеше секундта рөл, іске қосылған
  ереже және ақша қозғалысының картасы көрінеді.

### Кімге арналған

Қаржылық мониторинг талдаушысы. Сценарий: gid тізімін алу → деректерді жүктеу →
басымдық тізімін ашу → әр позиция бойынша негіздемені оқу → тереңдетілген
тексеруге жататын клиенттер тізімін және құқық қорғау органдарына сұраныс
дайындау.

### Негізгі қасиет

**Шешім «қара жәшік» емес.** Әр рөл — шегі бар формалды ереженің нәтижесі және
бұл ереже интерфейсте ол салыстырған сандармен бірге көрсетіледі. ЖИ-агенттер
қатысады, бірақ **рөлдерді тағайындамайды** (2-бөлімді қараңыз).

## 2. Архитектураның сипаттамасы

### Басты қағида

> **Агенттер зерттеу жүргізеді. Ережелер қозғалтқышы шешім шығарады.**

Агенттер *нені зерттеу керектігін, қаншалықты тереңдікте және шектер қандай
болуы тиіс екенін* шешеді. `roles.py` модулі метриканы шекпен салыстыра отырып,
*қандай рөл* екенін анықтайды және `RuleTrace` құрылымын жасайды — онда іске
қосылған ереже, пайдаланылған мәндер мен шектер сақталады. Техникалық
тапсырманың «түсіндірілетін ережесі жоқ рөл есептелмейді» талабы құрылымы
бойынша орындалады.

### Конвейер

```
жүктеу → деректерді профильдеу
       → [ЖОСПАРЛАУШЫ: осы деректерде қандай өтулер қажет]
       → граф → белгілер → уақыттық белгілер → атрибуция
       → [КАЛИБРЛЕУШІ: рөл шектері, симуляциямен және сақтаумен]
       → рөлдер (1-өту) → кластерлеу → рөлдер (2-өту: үйлестіруші)
       → басымдық → негіздемелер
       → [ТЕРГЕУШІ: досье] → [СЫНШЫ: қарсы дәлелдер]
       → [РЕДАКТОР: тұжырымдамалар] → [РЕВИЗОР: деректер сұраныстары]
       → файлдар
```

Толық схема: [`docs/diagram.md`](docs/diagram.md).

### Агенттер және олардың өкілеттіктері

| Агент | Нені шешеді | Оны не шектейді |
|---|---|---|
| **жоспарлаушы** | осы деректерде қандай өтулерді және қаншалықты тереңдікте іске қосу керек | `config.yaml` файлындағы қатаң шек, оны асыра алмайды |
| **калибрлеуші** | **барлық рөл шектерін**, әрқайсысына жазбаша негіздемемен | перцентильден шыққан диапазонда қалуға міндетті; ұсыныс **нақты деректерде симуляцияланады** және рөлді нөлдесе немесе бір рөлге желінің жартысынан көбін берсе қабылданбайды; нәтиже қайталанатындық үшін сақталады |
| **тергеуші** | әр басым шоттың айналасында нені зерттеу керек (көп қадамды функция шақыру циклі) | әр тұжырым функция нәтижесінен шығуға тиіс; аталған gid-тер бар болуы керек; сенімді **зиянсыз** түсіндірме ұсынуға міндетті |
| **сыншы** | қорытынды тізімде **не дұрыс емес**: жинау артефактілері, шектердің сезімталдығы, соқыр аймақтар | тек өзіне көрсетілген шоттарға сілтеме жасай алады; ештеңені төмендете алмайды — қорытындысы ұсынымдық сипатта |
| **редактор** | тек тұжырымдаманы | қайта жазылған сөйлемдегі әр сан `RuleTrace` ішінде болуға тиіс, әйтпесе нәтиже алынып тасталады |
| **жүктеуші** | кіріс файлдың қай бағаны неге сәйкес келеді | жауап қабылданғанға дейін деректердің өзімен тексеріледі |
| **ревизор** | жетіспейтін деректер сұраныстарын қалай тұжырымдау | олқылықтардың өзі графтан есептеледі |
| **талдаушы** | пайдаланушы сұрағына графқа қандай сұраныс жауап береді | тек функциялар нәтижесінен жауап береді; шақырулар хаттамасы жауаптың қасында көрсетіледі |

**Олардың ешқайсысы рөлді, бағаны, кластерді немесе тізімдегі орынды
тағайындамайды.** Әрқайсысының детерминделген қосалқы жолы бар:
`./agent_run.sh --offline` дәл сол үш CSV файлын дәл сол рөлдермен жасайды.

### Аудит журналы

`output_files/agent_log.md` әр агенттің жоспарын, әр функция шақыруын
аргументтері мен нәтижесімен, әр қабылданбаған шешімді себебімен және қосалқы
жолға ауысудың әрқайсысын тіркейді. Комплаенс міндеттерінде қорытындының қалай
алынғанын көрсете алмау — мәселенің өзі, сондықтан журнал нәтиженің бір бөлігі,
жөндеу файлы емес.

## 3. Пайдаланылған технологиялар

| Қабат | Технология | Не үшін |

| Деректер | `pandas`, `pyarrow`, `numpy` | parquet/CSV оқу, векторлық есептеулер |
| Графтар | `networkx` 3.7, `scipy` | бағытталған өлшенген граф, PageRank, betweenness, Louvain, байланыс компоненттері |
| Конфигурация | `PyYAML` | барлық шектер мен салмақтар кодтан тыс |
| Интерфейс | **меншікті фронтенд** (HTML/CSS/таза JS) | әдепкі: құрастыру қажет емес, желісіз жұмыс істейді |
| Интерфейс (балама) | `gradio` 5.50, `pyvis` 0.3.2 | екінші интерфейс, жалпыға ортақ сілтеме бере алады |
| Агенттер | `openai` (үйлесімді клиент), `python-dotenv` | ЖИ-қабаты; **орындалу кезінде міндетті емес** |
| Тесттер | `pytest` | 83 тест: файлдар келісімі, тұжырымдамалар, агенттер, интерфейс |

**Графиктер кітапханасы әдейі пайдаланылмайды.** Интерфейстегі жалғыз диаграмма
CSS-пен салынған: әйтпесе оның көрінуі JS-пакет пен Gradio фронтенді
нұсқаларының сәйкестігіне тәуелді болады.

**Қажет емес:** бұлт, GPU, ақылы қызметтер. Интернет тек сыртқы LLM API үшін
және ол қосылған жағдайда ғана қажет.

## 5. Іске қосу нұсқаулығы

### Бір команда

```bash
./agent_run.sh
```

Алты қадам: орта → тәуелділіктер → модельді тексеру → есептеу → файлдарды
тексеру → жалпыға қолжетімді сілтемесі бар веб-интерфейс.

### Режимдер

```bash
./agent_run.sh                 # ЖИ-қабатымен толық іске қосу (.env қажет)
./agent_run.sh --offline       # модельге жүгінбей; файлдар бірдей
./agent_run.sh --use-existing  # есептеуді өткізіп, алдыңғы нәтижеде интерфейсті ашу
./agent_run.sh --data ./my_export   # data/ орнына өз файлдарыңыз
./agent_run.sh --recalibrate   # калибрлеуші агентті қайта іске қосу
./agent_run.sh --no-app        # файлдар тексерілгеннен кейін тоқтау
./agent_run.sh --no-share      # интерфейс тек localhost-та
./agent_run.sh --port 7861
```

Қайтару кодтары: `0` — сәтті, `1` — есептеу сәтсіз, `2` — файлдар жоқ немесе
схемаға сәйкес емес, `3` — орта мәселесі. CI үшін жарамды.

### Бөліктер бойынша

```bash
.venv/bin/python run.py                  # тек есептеу: data/ → output_files/
.venv/bin/python run.py --only-profile   # тек деректер бойынша есеп
```

## 9. Рөл критерийлері

Барлық шектер — `config.yaml` ішінде, әрқайсысы алынған таралуын көрсетумен.
`MAX_DEPTH` тұрақты ретінде берілмей, деректерден оқылады.

| Рөл | Ереже | Шек | Негіздеме |
|---|---|---|---|
| `consolidator` (жинау нүктесі) | `in_deg >= min_payers` | 5 | p95 = 3, p99 = 6. 5 шегі 51 түйінді (2,3 %) таңдайды — «біреуден көп» емес, «әдеттен тыс көп төлеуші». |
| `distributor` (таратушы) | `out_deg >= min_recipients` **және** `out_deg >= fan_ratio × max(in_deg,1)` | 10, ×3 | p95 = 5, p99 = 24. 10 шегі 64 түйін береді; көбейткіш 56-ға дейін азайтады. |
| `transit` (транзит) | ағынның екі жағы да байқалады, `pass_ratio ∈ [0.8, 1.2]`, `in_deg < 5`, `out_deg < 10` | 0.8–1.2 | жолақта 70 түйін. Соманың ≥ 50 % 2 күн ішінде кетсе, сенімділік артады. |
| `terminal` (соңғы алушы) | шығыс тексерілген, `in_sum > 0`, `out_sum <= max_pass × in_sum` | 0.1 | **MAX_DEPTH деңгейінде ешқашан берілмейді.** Деректер табиғаты бойынша кең рөл, сондықтан басымдықта салмағы төмен. |
| `coordinator` (үйлестіруші) | consolidator шартынан өтеді **және** `n_key_payers >= 2` **және** `seed_reach >= p90` | 2, p90 | **басқа жинау нүктелерінен** жинайтын жинау нүктесі. Үш шарт та қажет. **10 шот, 0,4 %.** |
| `cutoff` (шолу шегі) | `depth == MAX_DEPTH` және ешбір ереже іске қосылмады | — | сөздіктің құжатталған кеңейтімі. Тұрақты сенімділік 0,7. |
| `peripheral` (перифериялық) | ештеңе іске қосылмады | — | 19 оқшауланған seed кіреді. |

**Сәйкес келгендегі басымдық:** `coordinator > consolidator > distributor >
transit > terminal > cutoff > peripheral`.

**Seed-клиенттер** ешқашан `transit` және `terminal` рөлін алмайды: олардың
кірісі деректер жинау тәсілінен төмендетілген, қатынас мағынасыз.

## Формулировкалар және құпиялылық

Әр жасалатын жол — `evidence`, `why`, `hypothesis`, деректер сұраныстарының
мәтіні, кез келген агент жауабы — адам туралы тұжырым емес, тексеруге арналған
болжам ретінде құрастырылған («жинау белгілері», «транзитке тән», «тексеруге
үміткер»). *criminal*, *guilty*, *launderer*, *organizer is*, *confirmed*
сөздері `config.yaml` ішінде қара тізімге енгізілген және әр агенттің
